# Current State

## Project Snapshot

Comite currently ships as a polished frontend-heavy reading platform with mock or browser-local persistence for most user and content behavior.

The core browsing and reading experience exists. The backend story is still thin outside the signed upload endpoint.

## Implemented Today

### Reader Experience

- Series browsing, search, and filtering
- Series detail pages
- Chapter reader pages
- Bookmarking
- Reading history
- Ratings
- Library and profile views

### User Experience

- Signup and login flows with local mock persistence
- Theme toggle with dark/light mode
- Typography now uses a dedicated body/display pairing with shared eyebrow and heading utilities instead of the previous default sans-only setup
- The `/welcome` route now acts as a distilled reading-first landing page centered on browse, resume, and featured picks instead of a feature-marketing grid
- The `/welcome` route now also uses a snippet-inspired announcement pill above the hero to surface resume or fresh-release context without adding another full content block
- The shell now uses the restored gradient wordmark plus snippet-inspired pill navigation and CTA treatments instead of the flatter interim header
- Carousel hero, series hero, and reader navigation now use shared theme overlay and foreground tokens instead of one-off black, white, and gray styling
- Alerts, status badges, modal backdrops, flair chips, and skeleton shimmer states now use shared theme helpers instead of raw red, gray, black, and white utility colors
- Signup now includes a live password confirmation preview, profile uses a ring-and-badge avatar treatment, and destructive account actions use a shared text-button interaction instead of plain secondary buttons
- Footer now uses a more expressive editorial composition with a large background wordmark and shared announcement pill treatment instead of a basic four-column block
- Browse list rows and chapter links are adapted for touch-first mobile use with 44px targets and less cramped metadata layouts
- Shared theme transitions are scoped to interactive surfaces, and the footer now uses deferred rendering to avoid work below the fold
- Notifications page
- Settings page
- Legal pages
- Not-found page for invalid routes
- Filter and drawer overlays support keyboard dismissal and focus restoration

### Admin Experience

- Admin dashboard shell
- Keyboard-openable command palette with accessible dismissal and SPA navigation
- Mobile admin header now exposes a dedicated jump action and collapsible nav instead of relying on the desktop link row
- Series admin page
- Chapters admin page
- Users admin page
- Tools admin page
- Upload admin page with direct-to-R2 signed uploads, server-side key and size validation, and visible upload failure messages

## What Is Still Mocked Or Simulated

- Authentication is localStorage-based and uses a hardcoded owner email.
- Series data is seeded from demo data in `dataService.ts` when storage is empty.
- Notifications are generated by client-side polling and random simulation.
- Admin analytics cards and charts are placeholders.
- Reports tooling is not backed by real report data.

## Known Gaps

- No automated tests are present.
- No real backend exists for content, auth, bookmarks, or reading sync.
- No persistent server-side datastore is wired in.
- `src/pages/legal/DMCAPage.tsx` still includes placeholder language.
- The repo still carries legacy Next.js artifacts even though Vite is canonical.

## Practical Interpretation

- Treat frontend behavior as real for UI and interaction work.
- Treat auth, content management, and user state as prototype-level unless the task explicitly adds backend infrastructure.
- Treat the upload flow as the main real server-integrated feature in the current repo.

## Documentation Maintenance Rules
